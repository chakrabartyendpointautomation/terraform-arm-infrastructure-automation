# Terraform & ARM Infrastructure Automation

A defensive Azure infrastructure-as-code portfolio lab showing the same small, non-production foundation in Terraform and Azure Resource Manager (ARM) JSON. It focuses on repeatable resource-group deployment, secure storage configuration, change review, and operational guardrails.

> **Status:** Portfolio example only. No Azure tenant was connected, no infrastructure was deployed, and no Terraform, ARM, Azure CLI, or PowerShell validation was run. Resource names and plan excerpts are synthetic.

## Why this project is separate

The existing portfolio focuses on endpoint and identity management: Intune and Jamf operations, Entra Conditional Access, endpoint remediation, provisioning, and certificate lifecycle. This repository isolates Azure infrastructure-as-code practices: provider constraints, template parameterization, plan/what-if review, state handling, and deployment controls.

## What is included

- terraform/: Terraform configuration for an Azure resource group and a locked-down storage account.
- arm/: ARM JSON template and synthetic parameters for the equivalent resource-group deployment.
- docs/: security guardrails and a pre-deployment review checklist.
- samples/: fictional Terraform plan excerpt for discussion only.

Both examples disable anonymous blob access and public network access, require HTTPS, set TLS 1.2 as the minimum, and disable shared-key authorization. They create no compute resources, public IPs, network rules, credentials, or data. The storage resource has no private endpoint and is not a ready-to-use production service.

## Prerequisites

Offline review needs only a text editor and JSON parser. Terraform review requires Terraform CLI and the AzureRM provider specified in terraform/main.tf. ARM validation and what-if require Azure CLI and a dedicated sandbox subscription with the required permissions. Authenticate using an approved local Azure CLI sign-in or workload identity; credentials are not configured or stored in this repository.

Never use a production subscription or commit credentials, plan files, or state files.

## Terraform review workflow

From the terraform/ directory:

~~~sh
terraform fmt -check -recursive
terraform init -backend=false
terraform validate
terraform plan -out=tfplan
terraform show -no-color tfplan
~~~

The first commands perform local configuration checks; init downloads the provider. Plan and show require Azure credentials and a target subscription. Review the complete plan before any apply. Do not commit tfplan or state. Terraform state may contain sensitive values. Shared environments need a remote backend with encryption, access controls, recovery, locking, and audit logging.

## ARM review workflow

The template deploys at resource-group scope; the resource group must already exist. In an approved lab subscription, validate and preview:

~~~sh
az account show
az deployment group validate --resource-group <lab-resource-group> --template-file arm/main.json --parameters @arm/parameters.example.json
az deployment group what-if --resource-group <lab-resource-group> --template-file arm/main.json --parameters @arm/parameters.example.json
~~~

Replace the placeholder with a disposable lab resource group. Review predicted creates, modifications, and deletions. What-if does not make changes, but is a prediction and may not capture every outcome. Do not run a deployment until a human reviews and approves the preview. No deployment command has been run for this repository.

The parameter file contains fictional non-secret values. Future secrets should use secure parameters or an approved Key Vault reference; never place secrets in ordinary outputs, tags, or logs.

## Safety and validation status

These are educational examples, not complete production blueprints or compliance guarantees. No Azure resources were created or modified. No tenant, subscription, customer data, credentials, or private endpoint is included. Public network access is disabled; real consumers would need a designed private connectivity path, DNS, routing, and monitoring. State backend, naming, region availability, policy, cost, data classification, retention, and recovery require environment-specific review.

No Terraform, ARM, Azure CLI, PowerShell, or cloud validation was run while preparing this repository. The commands above are proposed review steps, not completed test results.
